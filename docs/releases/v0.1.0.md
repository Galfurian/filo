First release of filo: direct messaging between interactive AI coding sessions in the same directory, without taking the sessions over.

**What it does**

- Connects live sessions of **Claude Code, Codex, Antigravity (agy) and OpenCode**. Each stays an ordinary interactive session; you keep typing to it while it works with the others.
- Sessions message each other by name (`filo send --to librarian ...`), and you start each one with a role: `/filo manager`, `/filo worker`, `/filo researcher`, `/filo librarian`, or your own profile in `~/.config/filo/profiles`.
- A session that is away gets its messages when it rejoins; one that runs `filo leave` is forgotten.
- Any other client can be added from a JSON file, with no code change.

**How a message gets in**

- Claude: a Monitor on `filo join`. Codex: `codex queue`. agy: `agentapi send-message`, using the session's own address and token. OpenCode: a plugin that starts `filo join` and turns each message into a prompt in the same session.

**Install and remove**

`./install.sh --dry-run` prints exactly what it will do; `./install.sh` only makes symbolic links, needs no sudo and changes no permissions. `./uninstall.sh` removes only those links.

**Systems**

Used day to day on Linux (Ubuntu 24.04 under WSL2). The tests also run on macOS in CI; the client integrations have not been tried on a Mac. Windows needs WSL.

**Security**

One user on one machine; not a network service. The runtime directory is private to the user and filo refuses one that is not. A message is untrusted input to a model, and `--from` is a label, not an identity. The agy and OpenCode integrations use interfaces that are not a stable public contract, so a client update can break them. The full model is in `SECURITY.md`. The archive is signed with Sigstore and has a build provenance attestation.
