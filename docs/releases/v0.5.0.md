`filo ui` is gone, and a session that works from another directory is told what to do.

**Removed**

- **`filo ui` and `ui/` (#72).** The browser viewer was an experiment. It is the one part of filo that served a page, its tests were slow on macOS (the server took about 35 seconds to print its address there), and it needed a security posture of its own. The command, the viewer, its tests and its documentation are removed. If you used it, stay on 0.4.9. The log of each scope (`events.jsonl`) and the client that a listener records stay.

**What is new**

- **The scope is said plainly (#69).** The skill told agents that the scope is the current directory and to stay in it, so an agent whose commands ran in a git worktree followed the text and wrote to a scope with nobody in it. The skill and the README now say that the scope is the one where the session joined or registered, and have a section for working from another directory.
- **`register` prints the scope (#69).** `registered as NAME for CLIENT session ID in /path`, and `"scope"` in the `--json` line.
- **`unreachable` names the scope it looked in (#69),** and points to `filo who --all` and `--scope`.

**Upgrade**

`filo upgrade`, or the one-line install again. `filo ui` no longer exists after it.

**Internal**

CI runs on Ubuntu 26.04, where `sleep` is one applet of a single binary: the test processes now name themselves (#71). CodeQL, ruff and ast-serialize are updated (#64, #65, #70), and Dependabot groups the CodeQL actions into one pull request.

**Security posture**

Smaller than 0.4.9: nothing in filo serves a page or listens on a network port any more. `get.sh` and `SHA256SUMS` are signed with Sigstore and covered by the build provenance.
