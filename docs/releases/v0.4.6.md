Claude Code sessions are now reached the way Codex and agy are, so a worker that does not arm its Monitor again no longer goes deaf, and a send says what happened to the message instead of "delivered" for what was only queued.

**What is new**

- **A Claude Code session is reached through its inbox socket (#52).** The Monitor of a Claude session ends after at most thirty minutes, and a worker that thought its work was over, or was idle when it ended, did not start it again and heard nothing of what came after. Claude Code binds an inbox socket for each session (2.1.224 and later), and a message written to it starts a turn even when the session is idle. `filo register --as claude` now records the session with its socket and token, and `filo send` writes into it: no listener, no Monitor, nothing to arm. The listener and the Monitor stay for a Claude Code without the socket, and `register` says so. Tried with one worker in auto mode; a session that skips permission prompts can have messages held for the user's approval, which was not tried.
- **A send says what happened, in one of four words (#53).** `delivered` (the recipient's listener has it), `queued` (handed to the queue or inbox of the client: Codex, agy, a Claude session, or left in the spool of a busy listener; the client reads it when it is free, and filo cannot see whether it did), `offline` (known, not connected; it arrives when the name joins again) and `unreachable` (an error, with the reason). Each line says what to do next: do not send it again, and do not wait for an answer here. `filo status` no longer calls a queued message "delivered".
- **`filo who` shows what waits (#53).** A Codex worker that works in one long turn never takes what is queued for it: nine messages were found, forty-seven minutes old, in Codex's queue for a thread that filo had reported as delivered. For a registered Codex session `filo who` now shows `3 waiting, oldest 30 min` (and `waiting`, `oldest_seconds` in its JSON), and a queued send says how many earlier messages are still waiting there. It is read from Codex's own queue database, a file that can change; what cannot be read is left out, and agy, Claude and adapters of the config file are listed as before.
- **`filo who` shows which listener runs an older filo (#54).** A listener goes on running the filo that started it, whatever is installed after. It now says `(runs filo 0.4.3, this is 0.4.6: it has to join again to use it)` next to one that differs.

**Changes in behaviour**

- The first word of what `send` prints is now the state, and an error starts with `unreachable:`. The id is still in parentheses after the name. `sent directly`, `left for` and `queued for NAME` in the old form are gone.
- `claude` is now the name of a built-in client: an adapters file that defines one is refused, as for `codex` and `agy`.
- Participants in the JSON of `who` and of `join --json` have a `version`.

**Upgrade**

`filo upgrade`, or the one-line install again. A listener that was started before the upgrade runs the old version until it joins again (`filo who` says which). For a Claude Code session with the inbox socket, run `/filo` again: it registers instead of starting a listener. For OpenCode 2 stop the background service (`opencode serve --service`) too, or the old plugin stays loaded.

**Security posture**

For a Claude Code session the registration file holds the path and token of its inbox socket, enough to write messages into that session; the file is `0600`, filo writes only to a socket of its own user, and SECURITY.md says it. Otherwise unchanged from 0.4.5: `get.sh` and `SHA256SUMS` are signed with Sigstore and covered by the build provenance.
