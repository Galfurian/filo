`filo ui --host IP` lets the viewer listen on an address that you give, to reach it from another computer.

**What is new**

- **`filo ui --host IP` (#62).** The address to listen on, IPv4 or IPv6 (`0.0.0.0` for all of them); `--port` was already optional. Without it nothing changes: `127.0.0.1`, this computer only. On an address that other computers reach, the viewer says when it starts that what it shows crosses the network unencrypted (a tunnel, `ssh -L`, is the safer way), and with `0.0.0.0` that the address it prints has to carry the computer's own address instead of `127.0.0.1`. A name is not accepted as `--host`.

**Changes in behaviour**

- The viewer answers only to the address it listens on (to any address of the computer, when it listens on all of them) and to `localhost`, never to another name, so a page on the web still cannot reach it through your browser; the token is still required.

**Upgrade**

`filo upgrade`, or the one-line install again. Restart `filo ui` to use `--host`.

**Security posture**

On `--host` with an address that other computers reach, the viewer is served over plain HTTP: the token and the text of the messages cross the network unencrypted, and anyone who has the address with its token can read them. SECURITY.md says so. Otherwise unchanged from 0.4.8: `get.sh` and `SHA256SUMS` are signed with Sigstore and covered by the build provenance.
