`filo boot` prints how a client connects, the skill is half as long, and the log of each scope is gone.

**What is new**

- **`filo boot` (#76).** It prints how the client that runs it connects and how a message reaches it: `register` for Codex, agy and Claude with an inbox socket, `join --detach` plus `watch` for Claude without one, the plugin tool for OpenCode. The client is picked from the environment; `--client NAME` says it when it cannot be told, and `--name NAME` is the name to connect under. The skill used to hold all of this, and every agent read all of it to use one part.
- **A shorter skill (#76).** `skills/filo/SKILL.md` goes from about 200 lines to about 100, and says to run `filo boot`. An agent with an older filo, which has no `filo boot`, is told to run `filo register --as <client>` instead; a Claude without an inbox socket then has a registration but no Monitor, so upgrade filo everywhere.
- **The property tests run every week (#75).** A workflow runs them with many more examples and a random seed, apart from the checks on a pull request.

**Removed**

- **The log of each scope, `events.jsonl` (#74).** It was written for the viewer that 0.5.0 removed, and nothing read it; it kept the text of every message on disk for a day. `FILO_NO_LOG` and `FILO_LOG_LIMIT` are gone with it. The client that a listener records stays, and `who` shows it. A file that an older filo wrote is not deleted: it sits in `/tmp` and goes with it.

**Upgrade**

`filo upgrade`, or the one-line install again. Listeners that are running keep the old code until they join again.

**Security posture**

Smaller than 0.5.0: filo no longer writes the text of the messages to a log. `get.sh` and `SHA256SUMS` are signed with Sigstore and covered by the build provenance.
