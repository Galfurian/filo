Fixes that came out of an audit of 0.1.0, one of them a change in behaviour for Codex. If you use Codex with filo, read the first section.

**Changes in behaviour**

- **filo no longer guesses which Codex session you mean.** Before, `send --to codex` with nobody registered, and `register` without a thread id, took the newest thread of the directory from Codex's own database. Both are gone. A message goes only to a session that registered itself: run `/filo` in Codex, and `register` needs `$CODEX_THREAD_ID` or `--session`. Sending to an unregistered `codex` is now an error that says so.
- **A registration is forgotten only when none of the client's processes run any more.** It used to keep the newest ones when fewer processes ran than there were registrations, which could keep the dead session and drop the live one. When it cannot tell which one ended it now keeps them all.
- **filo refuses a runtime directory it should not trust**: a link, a directory that is not yours, or one that is open to others and already holds a link or something of another user's. The same checks apply to the directory of every scope, and metadata files are read without following links.

**Fixes**

- **Two sessions registering at the same moment could end with the same name.** Eight simultaneous registrations lost or doubled a name in 18 runs out of 40; now it is 0 out of 40. A name is claimed by creating its file with a link, which only one process can do. `rename` claims its new name the same way.

**New**

- `filo --version`.
- `CONTRIBUTING.md`, a Code of Conduct, bug and feature forms and a pull request template.
- CI also checks the workflows with actionlint and zizmor.

**Security posture**

`main` is protected by a ruleset that applies to everyone: a pull request, five passing checks (Linux 3.10 and 3.12, macOS and CodeQL for Python and JavaScript), a linear history. Private vulnerability reporting is on; see `SECURITY.md`.

The archive is signed with Sigstore and has a build provenance attestation, as for 0.1.0.
