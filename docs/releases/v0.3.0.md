A message can no longer be lost to a shortened notification, and a message now says where it came from. If you use Claude, read the first section: a running Monitor has to be started again to get the fix.

**Changes in behaviour**

- **The Monitor of a Claude session starts with `--preview 400`.** A Claude Monitor shows only the start of a long line (about 500 characters) and cuts it without a mark, so the end of a message, often the instruction, could be lost without the reader knowing. The skill now starts it as `filo join --as NAME --json --preview 400`, and an agent that sees `"truncated": true` reads the whole message with `filo show ID`. A Monitor that is already running keeps the old behaviour until the session runs `/filo` again.
- **In every `message` event the body comes last**, after `from`, `id` and `reply`, so a client that cuts the end of a line still shows who wrote and how to answer. Only the order of the keys changed.
- **A message says where it was sent from.** The event has the `scope` of the listener, the `origin` (the directory the sender ran in) and, when that is another directory, `"foreign": true`; its `reply` command then carries `--scope` with that directory. For Codex, agy and OpenCode the text says "sent from DIRECTORY (another scope)". The skill tells an agent to pass a foreign message on to you and wait. `origin` is what the sender's process reports, as `--from` is: it lets an honest agent notice that a message crossed scopes and protects against nothing else.
- **The `participants` event of `join --json` lists registered sessions too** (`registered`). It was `[]` when only a Codex or agy session was there.

**New**

- `filo show ID` prints the whole text of a message you received (`--json` for the record). Each listener keeps what it receives, privately, for 24 hours.
- `filo join --json --preview N` cuts an event longer than N characters (at least 100) and says so: `"truncated": true`, the `length` of the whole message and `show`, the command that prints it. Without it an event is whole, which the OpenCode plugin needs.
- `filo who --all [--json]` lists every scope that has someone in it. A scope shows up once a session has joined or registered with this version.

**Upgrade**

`filo upgrade`, or the one-line install again. A session that was started before the upgrade runs the old version until it is restarted.

**Security posture**

Unchanged from 0.2.0: `get.sh` is signed with Sigstore, covered by the build provenance and listed in `SHA256SUMS`, like the archive. `SECURITY.md` now also describes what a listener keeps and what `origin` is worth.
