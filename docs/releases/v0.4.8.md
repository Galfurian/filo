A queue that is stuck is now said to be stuck, and a message in the viewer that has no text says why.

**What is new**

- **A stuck session is reported as stuck (#60).** When the oldest message in the queue of a client (Codex, for which filo can read it) has waited more than 30 minutes, `send` says that the session is likely stuck in one long turn and has read none of them, that the sender should not count on an answer, and that the user should interrupt it. Before, it said only "probably busy", which was read as normal. In the viewer the `N waiting · X min` badge turns red over the same threshold and the card of the session says `stuck?`.
- **The viewer says why a message has no text (#60).** `sent before this pool kept a log: its text is gone` for a message older than the log of the pool, `no text in the log: the filo of its sender did not write it` for one sent after it began.

**Fixes**

- A test that read the age of a queue as exactly 30 minutes no longer fails when the minute changes.

**Upgrade**

`filo upgrade`, or the one-line install again. Restart `filo ui` to have the red badge and the new wording. The warning in `send` is in the `filo` command that each agent runs, so it is there from the next message on.

**Security posture**

Unchanged from 0.4.7: `get.sh` and `SHA256SUMS` are signed with Sigstore and covered by the build provenance.
