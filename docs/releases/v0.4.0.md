A Claude session that leaves and rejoins no longer wakes everyone else, and a message says which scope it comes from correctly. If you use Claude with filo, read the first section: a session that is already running keeps the old behaviour until it runs `/filo` again.

**Changes in behaviour**

- **The listener of a Claude session is no longer its Monitor.** A Claude Monitor ends after at most 30 minutes. While the listener *was* the Monitor, each end told every other session that it left, and each restart that it joined, and every one of those notices woke them: one session's Monitor cost a turn to all the others, twice every half hour. The skill now starts `filo join --as NAME --detach --parent "$CLAUDE_PID"`, a listener in a process of its own that ends with the Claude session, and a Monitor on `filo watch --as NAME --preview 400`, which prints one JSON line per message and nothing else. Starting the Monitor again changes nothing for anyone and prints what came in meanwhile. A session started before the upgrade keeps its Monitor on `join` until it runs `/filo` again.
- **A message now says which scope its sender belongs to**, not the directory it happens to run in. An agent registered in a project that moved to a git worktree used to be reported as a stranger, with a reply command that failed. A `message` event has `"foreign": true` and `origin` (the sender's scope) only when the message comes from another scope, and its `reply` command then carries `--scope`; **the `scope` field is gone** from events, and an ordinary event is about 150 characters shorter. Keyword scopes work too. Codex, agy and OpenCode are told "sent from SCOPE (another scope)" in the same case.
- **`filo leave --name NAME` stops a listener** (it was an error before).
- **A message sent to a detached listener counts as delivered when the listener has it**, whether or not a `watch` is running.
- **The skill no longer tells an agent to stop at a message from another scope** and wait for you. It says who wrote and from where when it reports, and then decides as for any message, asking you first only when the message asks it to change files, run commands, send something elsewhere or do something outside its task. Nothing in a message is from the user, as before.

**New**

- `filo join --detach --parent PID`: a listener that goes on by itself, in a session of its own, and ends with `PID` or with `filo leave --name NAME`. It is not a service: no port, its own user only, and only when a session started it.
- `filo watch --as NAME [--preview N]`: the messages of a detached listener, one JSON line each, until it ends (`{"kind":"ended"}`). A message printed just as the previous `watch` ended can come again with the same id: filo may repeat one and never loses one.
- The README is ordered by use: quick start, profiles, commands, install and troubleshooting first; how it works, the clients one by one and the rest after, under a note that says the later sections are not needed to use filo.

**Upgrade**

`filo upgrade`, or the one-line install again. A session that was started before the upgrade runs the old version until it is restarted.

**Security posture**

Unchanged from 0.3.1: `get.sh` is signed with Sigstore, covered by the build provenance and listed in `SHA256SUMS`, like the archive. `SECURITY.md` now also describes what a detached listener is and is not, and says that `home` and `origin` are what the sender's process reports, as `--from` is.
