Three fixes from a second review. The first matters if you start several sessions at once: two of them could end up with the same name, and one could no longer be reached.

**Fixes**

- **Listeners that joined at the same moment could get the same name.** `join` looked for a name in use, removed the files of that name and bound a socket in three steps, and the metadata that says a name is in use is written only later. The second listener saw nothing, removed the socket that the first had just bound and bound its own: both were `claude`, the first could not be reached, and what was sent to `claude` went to the other. Eight `join --as same` started together gave three different names, some of them twice. A name is now held with a lock (`NAME.lock`) for as long as its listener lives, a detached one included; the system takes it back when the process ends, however it ends. The checks that existed (a registration of that name, a listener of an older filo) stay.
- **A client that sent a byte now and then could hold a listener for as long as it liked.** The timeout of a read started again with every byte, and a listener serves one connection at a time: while it was held nothing else was served, the spool was not delivered and the listener did not notice that its parent had ended. The whole message now has to arrive within the time, for the listener and for a client waiting for an answer. (It takes a process of your own user, which `SECURITY.md` puts out of scope; this is robustness.)
- **`filo upgrade` judged an address by how it began.** `http://127.0.0.1:80@example.org/` began like the local address that is allowed for a mirror and the tests, and is example.org. The address is now parsed: https, or http to 127.0.0.1 or localhost on a port, and never one that names a user. `upgrade` still insists on a `get.sh` stamped for the release, shows its dry run and asks before it runs it.

**Changes in behaviour**

None that you would notice. There is one more small file for each name that has had a listener, `NAME.lock`, in the runtime directory (`0600`), like the other state; it does not need to be cleaned.

**Upgrade**

`filo upgrade`, or the one-line install again. A session that was started before the upgrade runs the old version until it is restarted.

**Security posture**

Unchanged: `get.sh` is signed with Sigstore, covered by the build provenance and listed in `SHA256SUMS`, like the archive.
