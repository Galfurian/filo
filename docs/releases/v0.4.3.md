An agent that runs its commands in a git worktree of the project can now answer. If you use filo with Codex or agy in worktrees, upgrade: until then such an agent was told that a recipient who was connected was not.

**Fixes**

- **A registered session kept looking at the scope of the directory it ran in.** A scope is the directory a command runs in, and an agent does not always run its commands where its scope is. A Codex session registered in a project, whose commands ran in a worktree of it (`.worktrees/NAME`), looked at the scope of the worktree, found nobody (`filo who` said none) and `filo send` reported `recipient 'manager' is not connected`, while the manager, who wrote to the project, always reached it. Only `--scope` made it work, and only an agent that had been told to say it. This is how scopes have been chosen since the first version.

  Now `who`, `send`, `status`, `show`, `leave` and `rename` work in the scope where the session that runs them is registered, whichever directory its shell is in. The session is the one of the client that runs the command (`$CODEX_THREAD_ID`, `$ANTIGRAVITY_CONVERSATION_ID`, or the id variable of an adapter), and it is used when the current directory is another scope and holds no registration of it. `send` also uses the one scope where its `--from` name is a member, which covers a listener.

**Changes in behaviour**

- A command that works in another scope than its directory says so, on stderr: `filo: working in X, not in Y: this session is registered there (--scope chooses another)`. `who` names the scope it looked at, in the text and in the JSON.
- It is never a guess: when two scopes hold the session, or the name, nothing is inferred. `--scope` always wins. `join`, `register` and `watch` keep using the directory: they create the membership or read what a listener here keeps.
- A broken adapters file no longer stops a command that does not need it (`send` with a name that is a member of a scope, for example).

**Upgrade**

`filo upgrade`, or the one-line install again. A session that was started before the upgrade runs the old version until it is restarted; an agent in a worktree can use `--scope /path/of/the/project` until then.

**Security posture**

Unchanged from 0.4.2: `get.sh` is signed with Sigstore, covered by the build provenance and listed in `SHA256SUMS`, like the archive.
