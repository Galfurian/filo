A review of the whole repository, with seven fixes. If you use the Claude Monitor (`filo watch`), upgrade: a message could be left out of it, and the sender told that it was delivered.

**Fixes**

- **`watch` could skip a message when the clock of the system was set back.** It decided what to print by comparing the wall-clock stamps of two processes, and a message received after the clock went back looked older than the listener and was never printed, with no error. A listener now numbers what it receives and `watch` goes by the number. What an older filo wrote still works. (#50)
- **A message with bytes that are not UTF-8 was queued and then lost.** `send` took it for a message to an unreachable listener, spooled it, said "left for X" and the listener could not show it. It is now refused with a message, before anything is queued, and `--stdin` no longer ends in a traceback. (#44)
- **A message could be shown twice.** A sender whose wait for the answer ran out sent it again through the spool, and the listener showed both. A listener now ignores an id that it has kept. (#44)
- **A busy listener was removed as if it were gone.** With about 33 connections waiting, a connect failed at once and `who` or `send` deleted the live listener's files. The lock that a listener holds on its name is now the proof that it lives. (#45)
- **Listeners that ended together took 14 seconds.** Each told the others that it was leaving before it went, and those leaving too did not answer. They now go first and tell after. A detached listener also tells the others after the command that started it has its answer. (#45)
- **OpenCode plugin.** A join that was not answered yet could not be left, and a double `/filo` started two listeners. In OpenCode 2 a message could reach the session before the answer to `/filo`, and a listener that ended by itself left the session believing it was in the pool; the stream of events is subscribed again when it fails. In OpenCode 1 a prompt refused by an error was counted as delivered. `/filo --help x` no longer takes an option for a profile. (#47)
- **Smaller ones.** An adapter whose `process` has more than 15 characters lost its sessions; a delivery with a NUL, a client that writes bytes that are not text, a huge `--parent`, Ctrl-C in `watch`, and a server that does not speak HTTP in `upgrade` were tracebacks; the check for a new version read the release page on Python before 3.13; `upgrade` followed one level of link only. (#46)

**Changes in behaviour**

- `send` refuses a message that is not UTF-8 text.
- `/filo PROFILE NAME` with no such profile joins nothing, and the README and the skill now say so, as the OpenCode plugin already did; a single word that is not a profile is still a name.
- `install.sh` lists the directories that it will create, and `get.sh` takes a `FILO_HOME` that ends in `/` or `/.` and refuses `..` in it and a version that is not three numbers.
- A release is built only from a commit on `main`, and the workflow checks the tag and the release notes before it signs anything. `SHA256SUMS` is signed and attested like the archive and `get.sh`. (#48)
- The README says what it did not: `FILO_KNOWN_TTL`, `FILO_NO_PRUNE`, `FILO_BIN`, `FILO_RELEASE_URL`, the limit of a name, the lock files. (#49)

**Upgrade**

`filo upgrade`, or the one-line install again. A listener or a session that was started before the upgrade runs the old version until it is restarted, and a restarted `watch` goes on from where it was. For OpenCode 2 stop the background service (`opencode serve --service`) too, or the old plugin stays loaded.

**Security posture**

`SHA256SUMS` is now signed with Sigstore and covered by the build provenance, like the archive and `get.sh`. `filo upgrade` still checks https and the version stamp, and no signature; SECURITY.md says so and how to verify an upgrade by hand.
