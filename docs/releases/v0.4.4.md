The OpenCode plugin now loads in OpenCode 2. If you use filo with OpenCode 2, upgrade: until then filo did not load there at all.

**Fixes**

- **The OpenCode plugin did not load in OpenCode 2 (#39).** OpenCode 2 does not run a plugin written for OpenCode 1. It wants a default export with an `id` and a `setup`, and said "Plugin must export a default definition with an id and an effect or setup function"; `/filo` could not join anyone. The plugin now has one default export for both versions: `setup` for OpenCode 2 and `server` for OpenCode 1 (which reads it from 1.18.29). Tried with OpenCode 2.0.31: the plugin loads, `/filo tester` joins, and a message sent with `filo send` reaches the session as a prompt.

**Changes in behaviour**

- In OpenCode 2 the plugin registers `/filo` itself, and a message goes in with the session's own queue, which holds it until the step ends. The tools `filo_join` and `filo_leave` are there as before; `filo_join` has an optional `arguments`, and the command file and the skill tell the model to pass what the user typed after `/filo`. OpenCode 1 works as it did.
- The bug report form has an optional "Additional context" field (#40), for what no other field fits.

**Upgrade**

`filo upgrade`, or the one-line install again, then restart OpenCode. OpenCode 2 keeps a background service (`opencode serve --service`) that holds the plugin, so stopping the terminal is not enough: stop that process too, or the old plugin stays loaded.

**Security posture**

Unchanged from 0.4.3: `get.sh` is signed with Sigstore, covered by the build provenance and listed in `SHA256SUMS`, like the archive.
